This is why the chunk cadence is about 2.5 seconds

2.09 s inference plus 0.5 s of eight-step consumption brackets the measured 2500.4 ms cadence.

It gives the 16 Hz versus policy-refresh separation a measured cause.

What these numbers do not establish

  • The two rows used different checkpoints, and the server-side label is a command-line argument, not a value the server reported.
  • The inputs are synthetic images; this is a cost measurement, not a performance one.
  • The runtime log carries no version field, so its entries cannot be attributed to a checkpoint.

Follow-up work on the execution layer is ongoing and is not covered here.

Single-owner boundary

Read and command channels have separate owners.

camera_state_node exclusively owns Dobot FeedBack :30005 and both HIK/ZED camera devices. executor_supervisor_node exclusively owns Dashboard :29999 for MovJ, ServoJ, and ToolDO commands. The policy server is outside ROS2, so its inference latency rides on no topic here and is absent from the MCAP record — but a dedicated harness measures it on-device, and those numbers are reported above.

Compared with the Stage 2 collection system

The xArm6 pipeline separates human teleoperation and data collection across multiple packages and processes. The E6 pipeline runs observation, policy bridging, execution, and context as an autonomous loop within e6_vla_ros; there is no continuous human teleoperation point because the inference policy is the operator.
